ktbctl tui: adding things, and the edges
========================================

Adding (a)
----------

A menu of what can be added where you are:

      ┌ Add ─────────────────────────────────────────────────────┐
      │                                                          │
      │  > A bridge for a TNC, step by step (ktbctl setup)       │
      │    A port on ktbr1                                       │
      │    An empty bridge                                       │
      │    A TNC                                                 │
      │    A name for an adapter                                 │
      │                                                          │
      └─────────────────────────────────────────── Esc cancel ───┘

The first entry hands off to `ktbctl setup`: the TUI steps aside (the
terminal goes back to normal), the wizard runs as it does today, and the
TUI comes back when it's done, with the new bridge selected. The wizard
already does scanning, pairing, the model table's instructions and the
check at the end; doing it all again as TUI forms would be a second copy
to keep in step.

The rest are small forms in a dialog. A port, for example:

      ┌ Add a port to ktbr1 ─────────────────────────────────────┐
      │                                                          │
      │  Type    > ble-server   tcp-server   tcp-client          │
      │            spp-client   serial                           │
      │                                                          │
      │  Id        lan2                                          │
      │  Listen    wlan0:8002                                    │
      │  Allow     192.168.1.0/24          (empty: anyone)       │
      │                                                          │
      │  Anyone who can reach wlan0:8002 can transmit through    │
      │  your radio, under your callsign.                        │
      │                                                          │
      │       [ ⏎ Add ]     [ Esc Cancel ]                       │
      └──────────────────────────────────────────────────────────┘

The fields follow the type: an spp-client or serial port picks
its TNC from a list, a ble-server its adapter.

E (on anything dynamic) does the same hand-off to `ktbctl edit`, in
$EDITOR, for everything a form doesn't cover.
