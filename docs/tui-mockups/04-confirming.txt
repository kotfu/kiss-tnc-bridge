ktbctl tui: confirming, refusing, and errors
============================================

The consent rule, as in the CLI: anything that would disconnect someone is
tried with non_disruptive first, and if the daemon says it would disrupt,
the TUI shows exactly what and asks. Anything harmless just happens.

Disabling a bridge that's in use
--------------------------------

      ┌ Disable ktbr1 (TH-D75)? ─────────────────────────────────┐
      │                                                          │
      │  This would:                                             │
      │    • disconnect 1 app on ktbr1/phones                    │
      │    • close the link to TNC d75                           │
      │                                                          │
      │            [ y  Disable it ]     [ n  Cancel ]           │
      │                                                          │
      └──────────────────────────────────────────────────────────┘

Switching
---------

      ┌ Switch to ktbr2 (Shack relay)? ──────────────────────────┐
      │                                                          │
      │  ktbr2 needs TNC d75, which ktbr1 is using. Switching    │
      │  disables ktbr1 and enables ktbr2. This would:           │
      │    • disconnect 1 app on ktbr1/phones                    │
      │    • close ktbr1's link to TNC d75                       │
      │                                                          │
      │            [ y  Switch ]     [ n  Cancel ]               │
      │                                                          │
      └──────────────────────────────────────────────────────────┘

Removing something nobody's using still asks, since it's deleted
----------------------------------------------------------------

      ┌ Remove port lan from ktbr1? ─────────────────────────────┐
      │                                                          │
      │  Nobody is connected to it, so nothing is disrupted.     │
      │  It's removed from dynamic.toml.                         │
      │                                                          │
      │            [ y  Remove it ]     [ n  Cancel ]            │
      │                                                          │
      └──────────────────────────────────────────────────────────┘

Trying to change a static object
--------------------------------

      ┌ ktbr0 is in the config file ─────────────────────────────┐
      │                                                          │
      │  ktbr0 comes from /etc/kiss-tnc-bridge/config.toml, so   │
      │  only enabling and disabling it works from here. To      │
      │  change it, edit that file, then press R to reload.      │
      │                                                          │
      └─────────────────────────────────────────────── ⏎ close ──┘

Errors and refusals
-------------------

A refusal or error shows on the line above the keys, in red, until the
next key press. Results that need nothing from you ("ktbr1 enabled") show
there too, in the normal colour.
